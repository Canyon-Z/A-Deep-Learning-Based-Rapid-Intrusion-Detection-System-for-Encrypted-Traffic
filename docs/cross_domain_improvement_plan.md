# 跨域检测：现状、已实施的改进与长期路线

> 适用对象：本项目（加密流量二分类 + 流级六分类）的后续维护者与算法同学。
> 本文所有数字都能在仓库里复现，出处见附录 A。

---

## 摘要

1. **同源准确率不能外推到新环境。** 6 个模型在 USTC-TFC2016 测试集上都是 99.96%~99.99%，换到工业控制数据和 CSE-CIC-IDS2018 之后，同一个 MLP 的误报率从 0.04% 涨到 **99.91%**，AUC 只剩 0.10 的水平。
2. **模型的跨域排名会彻底翻转。** 同源最强的 CNN-BiLSTM 在 ICS 上 FPR 81.46%，而同源并不显眼的 Pure BiLSTM 只有 **0.63%**。所以「默认主力模型」这个设定在跨域场景下是错的，必须按域选。
3. **少量目标域标注是当前唯一被验证有效的补救手段。** 1000 条人工标注（其中 274 条攻击）把目标域检出率从 **0% 提到 97.21%**，FPR 2.94%。而无标签的 BN 统计校准（AdanB）实测**完全无效**（把模型校准成了全判良性）。
4. **"同形态、不同协议"的域漂移，任何分布距离方法都抓不到。** 实测 CIGI 仿真流量在会话图空间里与训练集 UDP 小包几乎重合（马氏距离比 0.19，正常范围），但它是一个模型从未见过的协议。这类漂移只能靠协议指纹（端口/魔数）或域分类器覆盖，见 §2.5 与 §3.3 T8。

已经落地的两项改进（本文第 2 节）：

- **A 连续域外分数**：把"这批流量有多陌生"从二元判断改成 0~1 的连续分数，用它在一套"同源权重"和一套"工业域权重"之间线性插值。
- **C 分歧度调权**：6 个模型票数僵持时，把权重掺向"换一个域也站得住"的模型。

两项都在 `DLIDS_ENSEMBLE_WEIGHTING=domain`（或界面上的「按域加权」）下生效，默认关闭。

**如果只能做一件事**：攒目标域标注数据。每域 1000 条（≥270 条攻击）就能把检出率从 0 拉到 97%，性价比高于任何算法改造。

## 1 现状

### 1.1 数据与模型

| 项目 | 内容 |
|---|---|
| 训练域 | USTC-TFC2016，1,957,416 条会话（28×28 字节图） |
| 二分类模型 | cnn_bilstm / classic_cnn / lightweight_cnn / pure_bilstm / mlp / transformer（6 个，`checkpoints/*.pth`） |
| 流级六分类 | `checkpoints/flow_multiclass.pth`，6 类（Benign/Bot/DoS-GoldenEye/DoS-Slowloris/DDoS-HOIC/DDoS-LOIC-UDP），温度 T=1.3772 |
| 跨域评估产物 | `logs/external_eval_test_ics.json`、`logs/external_eval_img_cse_cic_ids2018.json` |
| 跨域评估样本 | ICS：45,501 条（45,497 良性 / **4 恶意**）；CSE：13,020 条（11,354 / 1,666） |

**这两个评估集的恶意侧样本量差距极大，是本文后面所有结论的重要前提**：ICS 的 F1 建立在 4 条恶意样本上，一条错就是 25 个百分点；CSE 有 1,666 条但 AUC 只有 0.33~0.61。

### 1.3 四个已确认的事实

**事实 1：同源数字不能外推。** MLP 同源 accuracy 99.96%、AUC 0.9998；ICS 上 accuracy 0.10%、几乎把所有良性判成恶意。这不是训练 bug，是 28×28 字节图这个表示在不同协议族的字节分布下彻底变形的结果。

**事实 2：跨域排名会翻转。** 同源最优与 ICS 最优不是同一个模型，CSE 最优又是第三个（Classic CNN）。所以"选一个最强模型"这个思路在跨域下不成立，只能"按域选"或"按证据动态加权"（本文第 2 节）。

**事实 3：无标签校准无效。** `logs/adanb_eval.json`：目标域 1,044,525 条样本，baseline accuracy 72.59%、检出 0%；用 20% 数据（151,666 行）做 AdanB「BN 一阶二阶矩对齐」后 → accuracy 50.0%、检出 0%、FPR 0%，即**校准成了全判良性**。结论：重尾条件分布的均值/方差对不齐，这类方法在本任务上不成立。

**事实 4：少量目标域标注极其有效。** `logs/finetune_local.json`：同一 checkpoint，目标域 baseline accuracy 25.59%、检出 **0%**、FPR 0.026%；用 **1000 条标注**（其中 274 条攻击）、8 epochs、lr 1e-3 微调后 → accuracy **97.17%**、检出 **97.21%**、FPR 2.94%、precision 98.97%。1000 条标注换回 97 个百分点，这是全项目 ROI 最高的一次改进。

补充：跨天场景（同域不同日期）也会掉点。CIC-IDS2018 三天的实验里，跨天不加权的 accuracy 从 99.99% 掉到 72.60%，检出率掉到 **0%**；只有做特征侧改造（删端口 + log 化时长特征 + 批内标准化）才把检出拉回 31.52%，但 FPR 升到 15.35%。**纯统计特征在跨天场景下几乎不可用，字节图表示反而更稳**——这也是本项目继续用图像路线的原因。

## 2 已实施：连续域外分数（A）+ 分歧度调权（C）

### 2.1 为什么原来不够

原来的域识别是一条硬判断（`web/backend/main.py`）：

```python
_domain_now = 'ics' if industrial_sessions / total_sessions >= 0.30 else 'default'
```

其中"工业会话"靠端口白名单 `OUT_OF_TRAINING_PORTS` 命中（29 个端口、21 个协议：S7comm 102、Modbus 502、DNP3 19999/20000、EtherNet/IP 2222/44818、IEC-104 2404/2405、OPC-UA 4840/4843、BACnet 47808/47809、CODESYS 2455、OMRON FINS 9600、PCworx 1962、Red Lion 789、DHCP 67/68、SNMP 161/162、NTP 123、RTSP 554、SIP 5060/5061、AMQP 5672/5671、MQTT 1883/8883、CoAP 5683）。

三个洞：

1. **端口伪装**：工控恶意软件跑 8080，或 Modbus 隧道进 443 → 命中率 0 → 判成 default。
2. **加密隧道**：本项目做的是加密流量，DPI 拿不到应用层协议，只有端口恰好非标才命中。
3. **cse 域在 pcap 链路上无定义**：CSE 评估用的是 CIC-IDS2018 转的图像，不是 pcap。所以 pcap 输入实际只有 default/ics 两档。

### 2.2 方案 A：连续域外分数 + 权重插值

两个信号合成 0~1 的分数：

| 信号 | 定义 | 权重 | 依据 |
|---|---|---|---|
| `port` | 工业端口命中率 / 0.30，饱和到 1 | 0.6 | 协议族明确，最直接的证据 |
| `dist` | 批次平均对角马氏距离 / p99(2.6436)，0.5 以下记 0、2.0 以上饱和 | 0.4 | 与协议名无关，端口伪装时唯一还在说话的信号 |

```python
score = (0.6*port + 0.4*dist) / (0.6 + 0.4)     # 任一信号缺失则在剩下的信号里重新归一化
weights = (1 - score) * default_weights + score * ics_weights
```

**为什么不能用像素稀疏度**：`web/backend/main.py` 里 PIXEL_BASELINE 那段注释已经踩过这个坑——USTC 域内单文件像素均值跨度 122 倍（BitTorrent 0.0040 → World of Warcraft 0.4899，非零占比 1.38%~95.78%），比 USTC 与 ICS 的差距还大。任何全局阈值都会把 USTC 自己的良性文件（Facetime 0.0040 / Gmail 0.0116 / Skype 0.0078）误判成分布外。像素统计只做展示，不参与判定。

实测（`_domain_out_score` 直接喂输入）：

| 场景 | port | dist | score | 插值后 mlp 权重 | 插值后 pure_bilstm 权重 |
|---|---|---|---|---|---|
| 普通同源流量 | 0.0 | 0.0 | 0.000 | 1.000 | 1.000 |
| 真工控（命中 35%） | 1.0 | 0.0 | 0.600 | 0.419 | 1.375 |
| **端口伪装（命中 0，距离 1.5×p99）** | 0.0 | 0.667 | **0.267** | 0.742 | 1.167 |
| 端口伪装（命中 0，距离 3×p99） | 0.0 | 1.0 | 0.400 | 0.613 | 1.250 |
| 真工控 + 距离 2×p99 | 1.0 | 1.0 | 1.000 | 0.032 | 1.625 |
| 六分类没跑（dist=None） | 0.0 | — | 0.000 | 1.000 | 1.000 |

关键：**端口伪装下分数从 0 变成 0.267~0.400，权重开始向 ICS 侧倾斜**。这是原来二选一判断完全做不到的。

**一个必须强调的性质**：分数为 0 时插值结果就是 default 权重（全 1.0 = 等权）。所以域识别错了，最坏也只是退回等权，**不会比等权更差**。这是敢把它做成运行时可切的前提。

### 2.3 方案 C：分歧度调权

```
contest = 1 - |malware_votes - benign_votes| / total_votes     # 0=一边倒  1=完全对半
level   = clamp((contest - 0.34) / (0.99 - 0.34), 0, 1)        # 4:2 之前不介入
blend   = level * 0.6                                          # 最多掺 60%
weights = (1 - blend) * 域权重 + blend * 跨域稳健权重
```

其中「跨域稳健权重」的依据是 **`1 - max(FPR_ics, FPR_cse)`**，不是 F1：

- ICS 的 F1 建立在 **4 条恶意样本**上，一条错 25 个百分点，不能用；
- CSE 的 AUC 只有 0.33~0.61（接近随机），F1 同样是噪声；
- 两域唯一统计稳定的量是误报率（45,497 + 11,354 条良性样本支撑）；
- 取两域**最大**误报率而非平均：一个模型在某个域彻底失守就不该被听，平均会把失守摊平（MLP 在 ICS 上 FPR 99.91%）。

算出的跨域稳健权重：

| 模型 | 1−max(FPR) 依据 | 归一化权重 |
|---|---|---|
| Transformer | 39.11（ICS 0.33% / CSE 60.89%） | **1.7775** |
| Pure BiLSTM | 36.87（0.63% / 63.13%） | 1.6758 |
| Classic CNN | 32.49（67.51% / 37.97%） | 1.4768 |
| Lightweight CNN-BiLSTM | 12.53（14.55% / 87.47%） | 0.5697 |
| CNN-BiLSTM | 10.00（81.46% / 90.00%） | 0.4548 |
| MLP | 0.09（99.91% / 57.54%） | 0.0455 |

实测（在 6 个等权模型上叠加）：

| 票型 | contest | blend | Transformer | Pure BiLSTM | MLP |
|---|---|---|---|---|---|
| 6:0 / 5:1 | ≤0.333 | 0.000 | 1.000 | 1.000 | 1.000 |
| 4:2 | 0.667 | 0.302 | 1.234 | 1.204 | 0.712 |
| 3:3 | 1.000 | 0.600 | 1.466 | 1.405 | 0.427 |

语义：模型们意见一致时不动（等权就是最稳的估计）；只有吵起来时才向"换域也不崩"的那几个模型倾斜。

### 2.4 开关、观测与局限

**开关**：`DLIDS_ENSEMBLE_WEIGHTING=domain`，或「模型评估」页「分域投票权重」面板切换。默认 `off`，`off` 时上述代码路径全部不进入，判定结果与改动前逐位相同（`weighting='uniform'`、`weights_used=null`）。

**观测**：`/analyze` 响应的 `ensemble_weighting` 字段给出这次判定的取证信息：

```json
{"weighting": "domain", "domain_score": 0.6, "domain_signals": {"port": 1.0, "dist": 0.0},
 "batch_distance": 1.1408, "distance_threshold": 2.6436,
 "weights_used": {"pure_bilstm": 1.375, "mlp": 0.419, "...": "..."},
 "contest_strength": 0.6, "sessions": [{"contest": 0.333, "adjust": {"blend": 0.0}}]}
```

**局限（做之前就知道，不做掩饰）**：

1. **dist 通道缺真实回归样本。** 仓库里 ICS 原始 pcap 已随瘦身移除，无法用"陌生协议流量"做端到端回归；目前 dist 通道只有函数级验证 + 合成样本（载荷改 0x00 后距离 1.1408 未变，说明该合成手段不改变会话图，不能作为证据）。**这是下一阶段必须补的第一个实验。**
2. **cse 权重在 pcap 链路上用不到**，只有图像输入（`/analyze-flow` 的 CSV 路径）才有意义。
3. **A 的最强项是"不会更差"，不是"更好"。** 只有在 dist 信号真的能在陌生流量上抬起分数之后，A 才会带来增益。
4. **C 只在 domain 模式下生效。** off 模式保持等权是有意的：改动默认行为需要先有跨域回归数据。

### 2.5 已实测暴露的两个问题（2026-10 补充，都已修前者）

**问题一：端口表语义混淆，导致"非工控"被当成"工业域"。**

`OUT_OF_TRAINING_PORTS` 原本一张表混装 16 个工控协议与 13 个基础设施协议（DHCP/SNMP/NTP/RTSP/SIP/AMQP/MQTT/CoAP）。实测 `dhcp.pcap`：`port=1.00 → domain_score=0.600`，于是 DHCP 流量被套上了 ICS 权重 —— 它跟工控毫无关系。

"模型没见过这个协议"与"这是工业域"是两件事。已拆成两张表：

- `INDUSTRIAL_PROTOCOL_PORTS`（参与域判定的只有这张）：原 16 个 + 补充 CIGI 8002/8004/8005、PROFINET 34962-34964、HART-IP 5094、MELSEC 5007、GE SRTP 18245/18246、Beckhoff ADS 48898、Niagara Fox 1911/4911、FF-HSE 1089。
- `FOREIGN_PROTOCOL_PORTS`：DHCP/SNMP/NTP/RTSP/SIP/AMQP/MQTT/CoAP，只计入 `distribution.foreign_*` 供展示，不参与域外判定与加权。
- `OUT_OF_TRAINING_PORTS = 工业 + 外部`，仅用于原有"分布外拒判"逻辑。

修后实测：`dhcp.pcap` `port=0.00 → score 0.000`（等权）；`cigi2.pcap`（CIGI 仿真）`port=1.00 → score 0.600`，`domain` 模式下权重插值为 `{mlp:0.419, cnn_bilstm:0.698, classic_cnn:0.867, lightweight_cnn:1.278, transformer:1.363, pure_bilstm:1.375}` —— MLP 被压到 0.42，这正是想要的（MLP 在 ICS 域 FPR 99.91%）。

**问题二：形态相似但语义不同的域漂移，端口和距离都抓不到。**

`cigi2.pcap` 修复前 `dist_ratio=0.19`（远低于 0.5 下限，得 0 分）：它的会话图在特征空间里**看起来就像训练集里的 UDP 小包**，马氏距离完全正常。这类漂移的本质是"同形态、不同协议"，任何基于分布距离的方法都识别不出来。

这直接说明 A 的上限：**A 能覆盖"形态陌生"或"端口陌生"，覆盖不了"形态相同但协议不同"**。要覆盖后者只有两条路 —— 域分类器（用协议语义/时序指纹训练，见 §3.2），或把端口表做成可持续维护的资产（协议指纹库，见 §3.3 T8）。

## 3 长期方向

### 3.1 数据侧：要什么、要多少、怎么采

优先级从高到低。**这是整个路线里最该先做的部分**，因为算法改造的上限由数据决定。

| # | 数据类别 | 用途 | 最小可行量 | 理想量 | 采集方式 | 标注成本 |
|---|---|---|---|---|---|---|
| D1 | 目标域未标注流量 | 无监督 OOD 标定（马氏/Energy/KNN 的分位数）、域自适应训练 | 每域 **5,000 条**会话 | 每域 20,000 条 | 在目标环境抓包后自动切会话 | **0** |
| D2 | 目标域少量标注 | 目标域微调（已验证唯一有效） | 每域 **1,000 条**（其中 ≥270 条攻击） | 每域 3,000 条 | 从 D1 里分层抽样，人工确认 | 约 1,000 次人工判定/域 |
| D3 | 目标域全量标注 | 域分类器训练集 + 跨域评估基准 | 每域 **3,000 条/类** | 每域 10,000 条/类 | D1 + D2 扩充 | 3~10 倍 D2 |
| D4 | 六分类跨域标注 | 让六分类在目标域可用（当前只有同源指标） | 每类 **500 条** | 每类 2,000 条 | 结合 D2 的攻击样本做类型标注 | 按类数线性增长 |
| D5 | 误报/漏报样本 | 在线闭环、回归集 | 持续积累，起步 **500 条** | 无上限 | 复核中心的处置结论直接落库 | 已由复核中心承担 |

要点：

- **D1 是最高杠杆的零成本项**。有了每域 5,000 条未标注流量，就能把「距离阈值 p99」从同源值重标定到目标域，A 方案的 dist 通道立刻可用（现在这个通道的阈值 `2.6436` 是同源算出来的）。
- **D2 的 1,000/270 这个数字有实测支撑**（`logs/finetune_local.json`），不是拍脑袋。
- **D5 已经在跑了**：复核中心的「确认攻击 / 确认误报 / 忽略」结论就是标注，且带 `reviewed_by` 与 `note`。把它做成可导出的训练集是一条现成的低成本通道。
- ICS 评估集的问题必须解决：**4 条恶意样本无法评估任何检出能力**。至少补到 200 条恶意（同域 D3），否则所有跨域 F1 数字都不要拿来比较模型。

### 3.2 方案 B：域分类器

**目标**：给每一批输入打一个域标签（ustc / ics / cse），替代端口白名单。

**输入**：28×28 会话图 + 会话级统计（包长均值/方差、方向比、时长、字节熵）。只用与端口、IP、文件名完全无关的特征——否则会学到"端口=域"这种捷径。

**训练数据**：D3，每域 3,000 条/类起步。三类分类，macro-F1 目标 ≥0.90。

**收益**：端口伪装下也能识别域。

**风险（必须承认）**：

1. **二级误差**：域分类器错了，权重就错了。所以它只能作为 A 的**一个信号**（替换 `port` 分量），不能替换整个插值逻辑。
2. **标签噪声**：CSE 是图像转来的，与 pcap 不同源，混在一起训会让分类器学到数据集指纹而不是协议特征。
3. **不可外推**：新域来了它照样不认识。所以必须有"都不像 → 走连续分数"的兜底。

**实施门槛**：D3 齐备 + 一个独立 holdout 域（不参与训练）验证 macro-F1 ≥0.85 才上线。

### 3.3 其他提升跨域成功率的路线

按"证据强度 → 成本"排序。T0 已经验证过，其余全部未做。

**T0 目标域微调（已验证，首选）**
- 做法：冻结特征层，只重训分类头，或全量微调 8 epochs / lr 1e-3。
- 实测：1000 条标注 → 检出 0% → 97.21%，FPR 2.94%。
- 条件：D2（每域 1,000 条标注）。
- 成本：一次训练几十分钟。
- 风险：过拟合到目标域的那一段时间窗口，跨天仍会掉（跨天实验显示 accuracy 会掉到 72.60%）；需要定期重训。

**T1 测试时适应（TTA）**
- 做法：推理时用当前批次的统计量重估 BN 的均值/方差（BN-adapt）、或 Tent（熵最小化只调 BN 参数）。
- 预期：无标注、秒级生效，通常能挽回一部分跨域掉点。
- **注意**：本项目已经试过 AdanB（BN 一阶二阶矩对齐）**无效**——把模型校准成全判良性。原因写在 `logs/adanb_eval.json`：目标域条件分布重尾，均值差一个数量级也救不回来。所以 TTA 要做的话，应该用 Tent（只优化熵，不改全局统计），且必须先在 D1 上验证"不会整体塌成单一类"。
- 条件：D1（每域 5,000 条未标注，用来验证不塌）。
- 成本：低（改推理管线）。

**T2 域自适应训练（DANN / CORAL / MMD）**
- 做法：在特征层加域判别器（梯度反转），或对齐二阶统计（CORAL）、或用 MMD/Wasserstein 拉近源域与目标域的特征分布。
- 预期：能改善"目标域整体偏移"的情况；对"目标域攻击类型没见过"无能为力。
- 条件：D1（目标域未标注）+ 有源域训练管线可改。
- 成本：中（重训，需要调域损失权重）。
- 风险：本项目特征是 28×28 图像，域对齐在像素层意义有限，建议在 CNN 特征层对齐。

**T3 无监督 OOD 检测（补强 A 的 dist 通道）**
- 做法：在特征空间用 Mahalanobis（已在用）、Energy score（`-logsumexp(logits)`）、KNN 距离（对训练集特征的 k 近邻距离）、孤立森林。
- 预期：把"这批流量离训练分布多远"做准，直接喂给 A 的 `dist` 分量。
- 条件：D1（用来重标定目标域的分位数）。
- 成本：低（推理期计算，无需重训）。
- **这是下一步最该做的技术项**：A 的骨架已经在，缺的只是一个靠得住的距离标定。

**T4 表示鲁棒化（去捷径）**
- 做法：训练时随机化端口、IP、时间戳等与"域"高度相关的字段；多视图输入（字节图 + 包长序列 + 时序统计）。
- 预期：减少模型对"域指纹"的依赖，是 T0~T3 的前置改造。
- 证据：跨天实验里删端口 + log 化时长 + 批内标准化把检出从 0% 拉到 31.52%（代价是 FPR 15.35%），说明"特征里的捷径"确实是跨域失效的一大来源。
- 条件：无标注需求，但要重训。
- 成本：中（改特征管线 + 重训）。

**T5 集成多样性**
- 做法：不再 6 个模型都在同一份数据上学同一个任务；让其中 2~3 个用不同表示（字节图 / 序列 / 流统计）、不同数据增强。
- 预期：C 的分歧度调权才有意义——现在的 6 个模型同源训练，吵架时其实没有"更对的第三方"可听。
- 条件：无标注需求。
- 成本：中高（要训不同架构/不同输入的模型）。

**T6 在线反馈闭环**
- 做法：复核中心的处置结论 → 定期导出 → 增量微调 → 灰度上线（先在 off 模式跑影子对比）。
- 现状：复核中心已经能落库 `reviewed_by` / `note`，缺的是导出与增量训练脚本。
- 条件：D5 积累到 500 条以上。
- 成本：低（工程为主）。
- **这是把现有人工投入变成模型能力的唯一通道，建议尽早做。**

**T7 域分类器**：见 3.2，本质是 A 的一个信号源，优先级低于 T3/T6。

**T8 协议指纹库（端口表当资产维护）**
- 做法：不做"猜协议"，只维护一张可审计的协议指纹表：端口 + 协议名前缀/魔数 + 会话首包长度模式 + 方向比。每次遇到漏检（像 CIGI 那次）就补一条，附来源链接与样本名，进版本库。
- 现状：`INDUSTRIAL_PROTOCOL_PORTS` 已拆出并补了 13 条（CIGI/PROFINET/HART-IP/MELSEC/GE SRTP/Beckhoff/Niagara/FF-HSE），但仍是纯端口匹配。
- 条件：0 标注数据；需要一份"待补清单"（每次复核中心里判错但用户知道真实协议的样本）。
- 成本：极低，纯查表。
- 为什么值得：**A 抓不到的"同形态不同协议"漂移，端口表是最便宜的兜底**。它不优雅，但覆盖面随维护线性增长，而且每条都是可解释的（不像模型给个 0.99）。前提是别再把"基础设施协议"混进工业域 —— 这是 §2.5 踩过的坑。

### 3.4 评估协议与上线门槛

没有这套协议，所有改进都是"感觉变好了"。

**评估集**
- 每个域固定一份 holdout，**不参与任何训练/校准**；
- 恶意侧样本 ≥200 条（现在 ICS 只有 4 条，必须补）；
- 记录采集时间与采集环境，标注"同天/跨天"。

**必报指标**
`accuracy` / `检出率(recall_malware)` / `FPR` / `precision` / `AUC` / `macro-F1`，全部按域分别报。**禁止只报 accuracy**——45,497:4 的比例下，全判良性就有 99.99% 准确率。

**上线门槛（建议值）**
- 目标域 FPR ≤ 5%、检出率 ≥ 90%：可默认开启；
- 目标域 FPR ≤ 10%、检出率 ≥ 80%：只能 opt-in；
- 任一域 FPR > 15%：不得开启，回到等权。

**必须有的回归测试**
1. `off` 模式判定结果与改动前逐位相同（本仓库已有：`ensemble_weighting.weighting == 'uniform'`）；
2. 陌生流量（目标域 pcap）下 `domain_score` 显著 > 0（当前缺样本，待补）；
3. 3:3 僵持样本上 C 生效、6:0 样本上 C 不介入。

## 4 分阶段路线

| 阶段 | 目标 | 交付物 | 所需数据 | 验收标准 | 粗估工期 |
|---|---|---|---|---|---|
| **P0** | 把 A 的 dist 通道做实 | 目标域 pcap 回归集；重标定的 `_DIST_P99` | D1（每域 5,000 条，先做 ICS） | 陌生流量 `domain_score` ≥0.4，同源流量 ≤0.05 | 1~2 周 |
| **P1** | 标注闭环 | 复核中心导出 → 增量微调脚本 → 影子对比 | D2 + D5 | 微调后目标域检出 ≥90%、FPR ≤5%（复现 finetune_local 的结论） | 2~3 周 |
| **P2** | 无监督 OOD + TTA | Energy/KNN 分数接入 A；Tent 在 D1 上验证不塌 | D1 | 目标域 AUC ≥0.85，且不出现"全判一类" | 3~4 周 |
| **P3** | 域分类器 | 三类分类器 + 与 A 的 `port` 分量融合 | D3 | 独立 holdout 域 macro-F1 ≥0.85 | 4~6 周 |
| **P4** | 表示鲁棒化 + 集成多样性 | 去捷径训练 + 至少 2 个异构模型 | 无标注 | 跨域 FPR 相比 P0 基线下降 ≥三分之一 | 6~8 周 |

优先级判断：**P0 与 P1 是必做的**（一个让已有机制生效，一个复现已验证的最大收益）；P2 技术收益高但依赖 P0 的标定；P3/P4 属中期。

---

## 5 风险与限制

1. **数据比例陷阱**：ICS 45,497:4 这种比例下任何 accuracy/F1 都不可信。改进任何东西之前先修评估集。
2. **优化目标错位**：跨域场景的真实代价是"漏报一次入侵"vs"多一次误报"，两者不等价。当前所有指标都是等权统计的，实际部署应按代价加权（例如漏报 10 倍于误报），这会影响阈值选择。
3. **过度拟合评估集**：一旦开始用 ICS/CSE 调参，这两个域就不再是公正的 holdout。必须留一个域完全不看。
4. **加权不是万能**：A+C 只改变"听谁的"，不改变"模型见过什么"。没见过 ICS 攻击时，6 个模型都只能猜——真正的解药是 T0（目标域微调）与 D2（标注）。
5. **默认关闭是有意的**：改动默认判定行为前，必须先有 P0/P1 的跨域回归数据，否则就是拿生产环境当实验场。
